# Rapid Experience 実装ドキュメント (v1.2)

## 1. プロジェクト概要
**プロジェクト名**: Rapid Experience (略称: RapEx)
**コンセプト**: 「思考から遷移までのラグをゼロに」。日本人向けの「シンプルで」「スパッと一発で遷移できる気持ちよさ」に特化したランチャー拡張機能。
高機能なSalesforce Organizerとの差別化を図り、認知負荷の低いUIと、日本語・ローマ字入力のゆらぎ吸収を強みとする。

## 2. コア機能要件
1. **ショートカット起動**: 任意のショートカット（例: `Mac: Cmd + Shift + K` / `Win: Ctrl + Shift + K`）で、画面中央にコマンドパレット風の検索ボックスをオーバーレイ表示。
2. **インクリメンタルサーチ**: 文字入力のたびに遷移先候補を即座に絞り込み。
3. **キーボードナビゲーション**: 上下キーで選択、Enterで決定（遷移）。
4. **ゆらぎ吸収（日本人向け特化）**: ローマ字（`torihiki`）、ひらがな（`とりひき`）、英語（`Account`、`acc`）など、入力モードを気にせず検索可能。
5. **URL動的生成**: 現在開いているSalesforce組織のドメインに基づき、選択された項目の遷移先URLを動的生成。
6. **カスタムオブジェクトの動的取得**: 組織のカスタムオブジェクト情報をAPI経由で取得し、検索候補に自動追加する。
7. **レコードのグローバル検索**: 設定画面だけでなく、実データのレコードも検索候補に表示する。

## 3. システムアーキテクチャ
Chrome Extension Manifest V3 に準拠する。

* **`manifest.json`**:
  * 拡張機能設定、ショートカットキーの定義。
  * 必要な権限: `activeTab` (現在タブのURL取得), `scripting` (DOM挿入), `cookies` (API認証用セッションID取得), `storage` (セッションストレージ用)。
* **`content.js` (UI / 入力制御)**:
  * Salesforceのページ上にコマンドパレット（UI）をDOMとして注入・表示。
  * ユーザーのキー入力（起動、検索入力、矢印キー）を監視・制御。
* **`background.js` (Service Worker / データ制御・API通信)**:
  * SalesforceのCookie（`sid`）からセッションIDを取得し、Salesforce REST/Tooling APIを叩く。
  * APIから取得したデータをセッションストレージで管理する。
* **`style.css`**:
  * コマンドパレットのUIスタイリング（背景の暗転、入力ボックスのデザインなど）。モダンでミニマルなデザイン。

## 4. データ構造とマルチ環境対応（セキュリティ方針）
複数組織（本番、Sandbox、スクラッチ等）を行き来する開発者の運用に耐え、かつ機密情報を保護するため、データの持ち方を以下のように設計する。

### データ辞書の構成
* **静的辞書 (JSON)**: 標準オブジェクトや標準の設定画面など、どの組織でも共通するURLパスと検索用エイリアス。
* **動的辞書 (API取得)**: カスタムオブジェクト一覧など、組織ごとにユニークなメタデータ。

### 状態管理（`chrome.storage.session` の活用）
* 動的辞書のデータは、ハードディスク（ローカルストレージ）には保存しない。
* **`chrome.storage.session` (インメモリ)** を利用し、**「組織のドメイン」をキー**としてキャッシュする。
* **動作フロー**:
  1. 拡張機能起動時、現在の組織ドメインをキーにセッションストレージを確認。
  2. 未取得の場合：APIを叩いてデータを取得し、セッションストレージに保存。
  3. 取得済みの場合：API通信をスキップし、セッションストレージから即座にデータを返す（ラグゼロ）。
* **ライフサイクル**: ブラウザを閉じると全組織のキャッシュは自動で完全に破棄される。

## 5. 開発フェーズ

### フェーズ 1: MVP（静的データでのコアUI完成）
* **目的**: ランチャーとしての基本的な「気持ちよさ」を実装する。
* **実装内容**:
  * Manifest V3のセットアップと、`content.js`によるUI表示（ショートカットキー起動）。
  * 「設定ホーム」「標準オブジェクト（取引先など）」等、固定の静的データを用いた検索と画面遷移。
  * 日本語・ローマ字のゆらぎ吸収ロジックの実装。

### フェーズ 2: カスタムオブジェクトの動的取得（API連携基盤の構築）
* **目的**: 実務で使えるレベルに引き上げる。
* **実装内容**:
  * `background.js` にて、CookieからのセッションID取得処理を実装。
  * REST/Tooling APIを叩き、カスタムオブジェクト（`__c`）の一覧を取得。
  * 取得したデータを `chrome.storage.session` にキャッシュし、静的辞書とマージして検索候補に表示。

### フェーズ 3: レコード検索への拡張
* **目的**: 設定だけでなく、データへのアクセスもラグゼロにする。
* **実装内容**:
  * 検索キーワードが既存メニュー等にヒットしない場合、自動的にバックグラウンドでSOSLクエリを発行。
  * ヒットしたレコード（例: 取引先名や商談名）を候補に表示し、レコード詳細画面へ遷移。

### フェーズ 4: UXの高度化
* **目的**: 入力の手間をさらに省く。
* **実装内容**:
  * 開いている画面のコンテキスト認識（例：取引先画面なら取引先の設定を優先表示）。
  * コマンド機能の追加（例: 検索ボックスに `> reload` と入力すると、その組織のセッションキャッシュを破棄してAPIから再取得する機能）。

## 6. 将来の展望
* **コマンドパレット・アクション (`>`)**: 
  * `> clear cache` (Salesforceキャッシュクリア＆スーパーリロード)
  * `> login as [ユーザー名]` (代理ログインの実行)
  * `> create [オブジェクト名]` (新規作成モーダルの直接起動)
  * 遷移だけでなく、開発者向けの「アクション」もコマンドから実行可能にする。
